# Database Migration Review Workflow (db-migration)

Ensures zero-downtime, safe schema evolutions for the Handloom multi-tenant PostgreSQL database.

## Execution Lifecycle

### 1. UNDERSTAND

- Identify entity changes, relational constraints, foreign keys, and numeric precision requirements.

### 2. INSPECT

- Inspect `packages/database/prisma/schema.prisma` and previous migration history.
- Verify that no existing migrations are being modified or deleted.

### 3. PLAN

- Confirm adherence to standards:
  - UUID primary keys.
  - Mandatory `tenantId` foreign key.
  - Exact Decimal precision (`@db.Decimal(14, 2)` for currency, `@db.Decimal(12, 3)` for weights).
  - Explicit indexes on foreign keys and status columns.
- Plan Expand-and-Contract strategy for existing column alterations.

### 4. IMPLEMENT

- Edit `schema.prisma`.
- Generate Prisma Client: `pnpm db:generate`.
- **Require human approval** before executing any migration on staging or production databases.

### 5. TEST

- Verify Prisma Client generation exits with code 0.
- Execute full monorepo typecheck: `pnpm typecheck`.
- Run database unit and integration tests: `pnpm test`.

### 6. REVIEW

- Inspect SQL diff generated by Prisma migrate.
- Verify no `DROP TABLE` or destructive `DROP COLUMN` commands without backward-compatible backfills.

### 7. REPORT

- Document added models, relations, indexes, and migration script verification.
